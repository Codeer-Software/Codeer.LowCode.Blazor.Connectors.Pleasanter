# Pleasanter (プリザンターのサイトをモジュールにする)

「プリザンターの案件を一覧したい」「プリザンターのデータを画面から直したい」と言われたらこれ。
データソースがプリザンターのモジュールは、**DB のテーブルに結び付けたモジュールと同じ作り**で、読み書きの先がプリザンターのサイト (記録テーブル・期限付きテーブル) になる。
専用のフィールドは添付 (下の「添付」) だけで、スクリプトに専用のものは無い。URL・JSON・SQL を書くことも無い。

プリザンターのデータソースかどうかは、データソースの `ConnectionString` が `Provider=Pleasanter;` で始まることで分かる (`DataSourceType` は `PostgreSQL` と書かれている)。

```
Provider=Pleasanter;Url=https://example.com/pleasanter/;ApiKey=...;Sites=Projects:1200,Customers:1300
```

- 扱えるサイトは、接続文字列の `Sites` に `表名:サイトID` で並べたものだけ。**表名 (モジュールの `DbTable`) は `Sites` で付けた別名** (プリザンターのサイト名ではない)
- 要るサイトが `Sites` に無ければ、接続文字列に足してもらう (接続文字列は秘密の値を含むので、デザインのファイルに書かない・書き換えない。ユーザーに頼む)
- Wiki・フォルダ・ダッシュボード・サイト統合のサイトは表にできない

表の定義 (テーブルの定義) は、プロジェクトのサーバー専用ファイル (`ServerFiles/pleasanter.<データソース名>.metadata.json`) から読まれる (プリザンターには取りに行かない)。
このファイルはデザインと一緒に Web アプリへ配られ、Web アプリも表の定義をここから読む (モジュールが使う表がファイルに無いと、Web アプリの読み書きがエラーになる)。
プリザンターの表が 1 つも出てこない・要る表や列が無いときは、このファイルが無いか古い。
ユーザーにデザイナのメニュー **Tools > プリザンターのメタ情報を更新** を実行してもらう (このファイルを手で書き換えない)。更新したらデザインをデプロイし直してもらう。

## モジュールの作り方

DB のテーブルからモジュールを作るのと同じ手順 (テーブルの定義を読んで、列からフィールドを作る)。プリザンターのサイトがテーブル、項目が列として見える。

| モジュールの設定 | 書く値 |
|---|---|
| `DataSourceName` | プリザンターのデータソース名 |
| `DbTable` | `Sites` で付けた表名 (メタ情報のファイルの表の `Name`) |
| フィールドの `DbColumn` | プリザンターの内部の列名そのまま (`Title`・`ClassA`・`NumB`・`DateA`・`DescriptionA`・`CheckA` など。表示名 `LabelText` ではない) |
| Id フィールド | `DbColumn` は表のキーの列 (メタ情報のファイルの `Key`)。記録テーブルは `ResultId`、期限付きテーブルは `IssueId` |

- Id はプリザンターが採番する。Id フィールドを手入力にしない (既定のまま)
- フィールドの `DisplayName` (ラベル) には、メタ情報のファイルの列の `LabelText` (プリザンターの画面の項目名) を使う。
  `LabelText` が無い標準の列はプリザンターの既定の名前: `Title` タイトル・`Body` 内容・`Status` 状況・`Manager` 管理者・`Owner` 担当者・`StartTime` 開始・`CompletionTime` 完了・
  `WorkValue` 作業量・`ProgressRate` 進捗率・`RemainingWorkValue` 残作業量・`CreatedTime` 作成日時・`UpdatedTime` 更新日時・`Creator` 作成者・`Updator` 更新者・`Ver` バージョン。
  `LabelText` の無い拡張の列 (`ClassA` など) は、列名を見せずにユーザーに項目の意味を聞く
- 使う列だけをフィールドにする。フィールドにしていない列は読みも書きもしない
- モジュールの名前を表名 (`Sites` の別名) と同じにしなくてよい。`Task` のようにスクリプトの型の名前と重なる名前は付けられない (設計チェックのエラーになる)。`WorkTask` などにする
- 一覧には表示件数 (ページング) を付ける。件数を絞らない読み出しは上限 (接続文字列の `MaxRows`、既定 10000 行) を超えるとエラーになる

### 列の種類とフィールド

メタ情報のファイルの列の `Kind`:

| `Kind` | 列 | フィールド |
|---|---|---|
| `String` | `Title`・`Body`・`ClassA`…・`DescriptionA`… | TextField。`Body`・`Description` の列は `IsMultiline: true` |
| `Number` | `NumA`…・`Status`・`Manager`・`Owner`・`WorkValue`・`ProgressRate` など | NumberField。`Format` を書く (小数の桁が `8.0000` のように出るので、整数なら `#,0`、小数を持つ列 (`WorkValue`・`ProgressRate` など) は `#,0.##`) |
| `Date` | 日付だけの `DateA`… (プリザンターの書式が年月日) | DateField (時刻の入った値もその日として読み・検索する) |
| `DateTime` | 時刻を持つ `DateA`…・`StartTime`・`CompletionTime`・`CreatedTime`・`UpdatedTime` | DateTimeField。**`SaveAsUtc` は false のまま** (プリザンターの日時は API キーの利用者のタイムゾーンの壁時計の値のまま読み書きされる) |
| `Bool` | `CheckA`… | BooleanField。BooleanField の `Text` (チェックボックスの横の文字) を書く |
| `String` (`Comments`) | コメント | 下の「コメント」 |
| `Attachments` | `AttachmentsA`… (添付) | プリザンターの添付 (`Codeer.LowCode.Blazor.Connectors.Pleasanter.PleasanterAttachmentsFieldDesign`)。下の「添付」 |

- 数値の列で `Nullable` が false のもの (プリザンターの既定) は、空にすると 0 になる (読むと 0)。空と 0 を区別したい列は、プリザンターの項目の設定で null を許してもらう
- チェックの列は空を持たない (空はチェックなし)
- `Status` (状況)・`Manager` (管理者)・`Owner` (担当者) は数値で読める。`Manager` / `Owner` / `Creator` / `Updator` はプリザンターの利用者の ID (名前にはならない。コネクターは利用者の表を読まない)。一覧に出すなら読み取り専用の数値として見せる
- `Locked` は列として出てこない。FileField・ImageField は結べない (添付の列にもプリザンターの添付のフィールドだけを結ぶ)
- 選択肢が利用者 (`[[Users]]` など) の文字の列で、検索の値に `Own` を書いても「自分」にはならない (文字の `Own` と比べる)

### コメント

`Comments` の列 (どの表にもある) はプリザンターのレコードのコメント。

- 読むと、コメントの一覧の JSON の文字 (`[{"CommentId","CreatedTime","Creator","Body"}...]`・新しい順・無ければ `[]`)
- 書くと、空でない文字がコメント 1 件として足される (前のコメントは変わらない・消せない)。空なら何もしない
- フィールドは TextField (`IsMultiline: true`)。読み込んだレコードではフィールドに JSON が入るので、既定は表示だけ (`IsViewOnly: true`) にする。
  入力させるのは新規作成の画面 (最初のコメント) に限る。既存のレコードで入力させると、読み込んだ JSON を書き換えた文字がそのまま 1 件のコメントとして足される
  (変えずに保存すれば送られない)
- 検索の条件・並び・集計の軸や値に使わない (エラーになる)

### 添付

メタ情報の `Kind` が `Attachments` の列 (`AttachmentsA`…。サイトのエディタか一覧に出ている添付の項目) は、プリザンターの添付のフィールドに結ぶ。1 つのフィールドでその列のファイルの一覧・ダウンロード・追加 (複数)・削除を扱う。

```json
{
  "DbColumn": "AttachmentsA",
  "MaxFileSizeMB": 10,
  "DisplayName": "資料",
  "Name": "Attachments",
  "TypeFullName": "Codeer.LowCode.Blazor.Connectors.Pleasanter.PleasanterAttachmentsFieldDesign"
}
```

- `MaxFileSizeMB`: 1 ファイルの上限 (MB・既定 10・1 以上)。画面で足すときの確かめで、超えるファイルは画面で足せない (入力エラー)。サーバーでは確かめない (サーバー側の上限はプリザンターの項目の設定 `LimitSize` とアプリの要求の大きさの上限)
- 値はファイルの一覧の JSON の文字 (`[{"Guid","Name","Size"}...]`)。保存で送られるのは足すファイル (`{"Name","ContentType","Base64"}`) と消すファイル (`{"Guid","Deleted":true}`) だけで、消せるのはそのレコードのその列のファイルだけ
- 足す・消すは保存したときに送られる。新しいレコードでも足せる。ダウンロードのリンクは保存済みのファイルだけ (ダウンロードの口はアプリのホストが置く)
- 一覧のレイアウトの列に置くとファイル名だけが並ぶ。その列は `CanUserSort: false` にする (並べ替えに使えない)
- 検索の条件・並び・集計に使わない (エラーになる)。検索のレイアウトに置かない
- `IsViewOnly`・`IsEnabled`・権限はほかのフィールドと同じ。`IsRequired` は「ファイルが 1 つ以上」
- レコードのコピーでは写らない (コピーしたレコードは添付なしで始まる)
- 値とファイルの操作はスクリプトに出ていない (足す・消すは画面の操作だけ)

### 選択肢 (Enum に写す)

選択肢を持つ列は、メタ情報のファイルの列に `Choices` (値 `Value` と表示 `DisplayText` の並び) がある。

- **文字の列 (`Kind` が `String`。`ClassA` など)** の選択肢は、Enum の定義に写して SelectField にする。
  Enum の定義 `Enums/<名前>.enum.json` を 1 つ作り (`Name` は列の `LabelText` から付けた識別子)、`Members` は `Choices` の順に `Name` = 値 (`Value`)、`DisplayText` = 表示 (`DisplayText` が無ければ書かない)。
  値が識別子として使えない文字 (空白・記号・数字で始まる) を含むなら、`Name` を別の識別子にして `Value` に値をそのまま書く。
  列のフィールドを SelectField にして、`EnumName` に Enum の名前を書く。保存されるのは値 (`Value`)、画面に出るのは表示
- **数値の列 (`Status` など)** の選択肢も Enum の定義に写して SelectField にする。Enum の定義に `"ValueType": "Number"` を書き、`Members` は `Choices` の順に `Name` = 表示 (`DisplayText`)、`Value` = 値の数字 (`"100"` のように文字で書く)。
  画面には表示が出て、保存されるのは数字。検索の条件もそのまま使える。`Choices` の無い数値の列 (選択肢を設定していない `Status` など) は NumberField のまま
- 複数選択の列 (`"MultipleSelections": true`) は SelectField にしない。TextField で `IsViewOnly: true` にする (値の持ち方をコネクターは解釈しない)
- 選択肢の中身はプリザンターから読み直さない (Enum の定義が正)。プリザンターで選択肢を変えたら、メタ情報を更新して Enum の定義を直す
- 選択肢が利用者・組織 (`[[Users]]` など) の列は `Choices` に出てこない。値 (ID) のまま扱う

### ほかのサイトを指す列 (リンク)

プリザンターで別のサイトへのリンクにした列 (選択肢が `[[サイトID]]`) は、メタ情報のファイルの列に `LinkSiteId` (相手のサイト ID) がある。
相手のサイトが `Sites` にあれば `LinkTable` (相手の表名) も入る。

- `LinkTable` のある列は、その表のモジュールを作って LinkField で結ぶ (`DbColumn` = リンクの列 (`ClassA` など)、`SearchCondition.ModuleName` = 相手のモジュール、`ValueVariable: "Id.Value"`、`DisplayTextVariable` = 見せる項目 (相手の `Title` のフィールドなど))。
  列に入るのは相手のレコードの ID。一覧・詳細で相手の項目が出る。候補から選ばせるなら SelectField でもよい
- `LinkSiteId` があって `LinkTable` が無い列は、相手のサイトが `Sites` に無い。LinkField にするなら、ユーザーに相手のサイトを `Sites` に足してもらってからメタ情報を更新する
- 結べるのは同じプリザンターのデータソースのモジュール同士だけ。プリザンターのモジュールと DB のモジュールを LinkField の結合で結ばない

### 読み取り専用の列

キー (`ResultId` / `IssueId`)・`Ver`・`Creator`・`Updator`・`CreatedTime`・`UpdatedTime`・`RemainingWorkValue` (残作業量。作業量と進捗率から計算される) は、
テーブルの定義で読み取り専用の列 (メタ情報のファイルの `"ReadOnly": true`) になっている。

- 普通のフィールド (NumberField・DateTimeField など) を結び、**詳細・一覧のレイアウトで `IsViewOnly: true`** にする (表示だけ)
- `IsRequired` にしない
- 作成では、キー以外の読み取り専用の列に値があっても送らない (プリザンターが決める。レコードのコピー (CopyModuleButtonField) が作成日時などの値を写しても保存できる)。
  更新でこれらの列に値を書くとエラー。作成でキーに値を入れてもエラー
- **フィールド名を `CreatedAt` / `UpdatedAt` / `Creator` / `Updater` / `DeletedAt` / `Deleter` にしない。** この名前は CLB のシステムフィールドになり、CLB が値を書く。
  `UpdatedAt` / `Updater` は更新のたびに、`DeletedAt` / `Deleter` は削除 (論理削除になる) で書かれ、読み取り専用の列なので保存がエラーになる。
  `CreatedAt` / `Creator` は作成のときだけ書かれ、エラーにはならないが値は送られない。`CreatedTime` の列なら `Created` などの名前にする
- 値は保存のあとで読み直すと出る (保存の前の画面では空・前の値のまま)

### タイトル

`Title` の列は、そのままタイトルになるサイト (メタ情報のファイルの表の `TitleIsRaw` が true) と、プリザンターが複数の項目からタイトルを作るサイト (`false`) がある。
`TitleIsRaw` が false の表では、`Title` の値はプリザンターの画面に出るタイトルと違うことがある。画面と同じ見え方にしたいときは、タイトルを作っている元の項目をフィールドにする。
その表の `Title` での検索・並びは、コネクターが条件に合う行を全部読んで行う (下の「検索・並び」の件数の上限)。

### 必須

プリザンターで入力必須の項目も、列としては空を許す形で見える。必須かどうかは保存のときにプリザンターが確かめ、足りなければ保存がエラーになる。
画面で先に止めたいときは、フィールドを `IsRequired: true` にする。

### 親子 (明細を親の詳細の中で編集する)

DB の親子と同じ作り。子のサイトに親へのリンクの列があれば、親のモジュールに子の一覧 (ListField) を置ける。

| 設定 | 書く値 |
|---|---|
| 子のモジュール | 子の表 (`DbTable`)。親へのリンクの列は LinkField (親のモジュールへ) にする |
| 親の ListField の `SearchCondition` | `ModuleName` = 子のモジュール、`LimitCount` は付けない、`Condition` に `FieldVariableMatchCondition` (`SearchTargetVariable` = 子の LinkField の `Value`、`Variable: "Id.Value"`) |
| 親の ListField | 子を画面で足す・直す・消すなら `CanCreate` / `CanUpdate` / `CanDelete` を true |

- 子の行は 1 件ずつプリザンターに書かれる。途中で失敗したとき、そこまでに書いた行は残る (下の「保存」)

### 楽観ロック

`UpdatedTime` の列に、`Name: "OptimisticLocking"` の OptimisticLockingField (`IncrementVersion: false`) を結ぶ。
更新の前に、読んだときから更新日時が変わっていないかを確かめてから書く (確かめてから書くまでのわずかな間に入った別の更新は防げない)。レイアウトには置かない。

## 検索・並び

使えるもの: 比較 (等しい・等しくない・大小)・部分一致・空欄・候補の中のどれか (In)・and / or / not・日付や数値の範囲・並び・ページング・件数。
LinkField の値 (相手の ID) での検索、LinkField 越しの項目の表示もできる。

DB のモジュールと同じ書き方で使えるもの (コネクターが相手の表を先に読んで値を集める):

- LinkField 越しの項目 (`Customer.Name` のような、相手の表の列) での検索・並び
- 子の一覧の項目での検索 (すべて含む・存在する/しない)
- 集計 (件数・重複なしの件数・合計・平均・最小・最大。軸・条件・集計後の絞り込み・並び・上位の件数)。プリザンターに集計の API は無いので、コネクターが条件に合う行を全部読んで集計する。
  行と列の 2 つの軸のクロス集計で上位の行だけを出すとき (行の合計・総計をその行の分だけで出す) も使える
- 日付の項目を期間 (年・四半期・月・週・日・時) でまとめる集計の軸 (`DateGroup`。年度の開始月 `FiscalYearStartMonth` も使える)

件数の上限 (接続文字列の `MaxRows`、既定 10000) を超えるとエラーになるもの (コネクターが条件に合う行を全部読む):

- 集計 (条件に合う行の数が上限を超えるとき)
- LinkField 越しの項目・子の一覧の項目での検索で、相手の表に当たるレコード
- LinkField 越しの項目・リンクの列・`TitleIsRaw` が false の表の `Title` での並び
- プリザンターの検索の条件にそのまま書けない条件 (等しくない・否定・空でない・候補に無い (NotIn)・より大きい / より小さい (以上・以下は書ける)・複数選択の列の条件・`RemainingWorkValue` の条件など) を含む検索。
  条件を広げて読み、コネクターが絞る。件数の多い一覧では、こうした条件だけで探させず、ほかの条件 (等しい・以上・以下・部分一致・空欄) で絞れるようにする

使えないもの (エラーになる):

- 列どうしの比較・JSON の列のノード・意味検索のようなフィールド独自の検索条件
- `Comments` の列・添付の列での検索・並び・集計

文字の比較: 等しいは大文字・小文字を区別し、部分一致は区別しない (PostgreSQL のプリザンター)。プリザンターの DB の種類によって変わることがある。
LinkField 越しの項目などでコネクターが並べるときは、空欄は昇順で先 (文字)・後 (数値・日付)、文字は文字コードの順になり、プリザンターの画面の並びと違うことがある。

## 保存

- **プリザンターへの保存はレコード 1 件ごとに確定する。** 同じ保存の中のほかの処理が失敗しても戻らない (ロールバックしない)。
  1 回の保存でプリザンターのレコードを複数書く画面 (親と明細) や、プリザンターと DB を一緒に書く画面は、途中まで保存された状態が起こりうる。
  そろっていないと困る組み合わせは、画面 (保存の単位) を分ける
- 更新は変えたフィールドだけを送る
- 読み書きは接続文字列の API キーの利用者 (連携用) の権限で行われる。画面のユーザーごとの読み書きの制限は、モジュールの権限で決める
- プリザンターの入力の検証で止まれば保存がエラーになる

## ExecuteSqlField (プリザンターの拡張 SQL)

プリザンターのデータソースの ExecuteSqlField は、プリザンターの拡張 SQL を呼ぶときだけ使う。

| 設定 | 書く値 |
|---|---|
| `CommandType` | `StoredProcedure` (SQL 文 `Sql` はエラー) |
| `CommandText` | 拡張 SQL の名前 (プリザンターの `ExtendedSqls` の `Name`)。プリザンター側で `"Api": true` にしてあるもの |
| 入力のパラメータ | 名前はモジュールのフィールドの `DbColumn` と同じにする (一致しないパラメータは送られない)。その名前が拡張 SQL の中の `@名前` になる (`@` は付けない)。プリザンターの表を持つモジュールでは `DbColumn` が列名なので `@ClassA` のようになる。値の無いパラメータは渡せない (エラー) |
| 出力のパラメータ | 拡張 SQL が返す最初の行の、同じ名前の列の値が入る |
| `MethodType` | `Scalar` なら戻り値は最初の行の先頭の列の値。`NonQuery` の戻り値は -1 (件数は分からない) |

- 拡張 SQL はユーザーにプリザンター側へ置いてもらう (デザインでは作れない)。名前を推測して書かない
- 失敗してもやり直さない。拡張 SQL が無い・パラメータが足りないなどはエラーになり、実行されたかどうかは分からない

## やってはいけないこと

- **プリザンターのデータソースで SQL を書かない** (QueryField のモジュール、ExecuteSqlField の SQL 文)。ExecuteSqlField は拡張 SQL の呼び出し (`StoredProcedure`) だけ
- **DateTimeField を `SaveAsUtc: true` にしない**。プリザンターの日時は壁時計の値なので、UTC にするとずれる
- **読み取り専用の列を入力できるレイアウトに置かない・システムフィールドの名前 (`CreatedAt` など) を付けない** (更新・削除の保存がエラーになる)
- **`DbTable` にプリザンターのサイト名やサイト ID を書かない** (`Sites` で付けた表名を書く)
- **1 回の保存でプリザンターのレコードと DB のテーブルの両方がそろって保存される前提にしない** (上の「保存」)
- **プリザンターのモジュールと DB のモジュールを LinkField の結合で結ばない**

## 扱えないもの

- 画像の項目・ロック・プロセス (添付は上の「添付」のフィールドで扱う)
- 利用者・組織の名前の表示 (ID のまま)
- Wiki・フォルダ・ダッシュボード・サイト統合のサイト
- 選択肢の候補をプリザンターから画面のたびに読むこと (Enum の定義に写して使う)
- 上の「使えないもの」の集計・検索
